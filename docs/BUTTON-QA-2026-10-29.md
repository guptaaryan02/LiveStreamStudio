# LiveStream Studio 1.0.2 — button and behavior audit

**Update:** The theme, desktop notification and analytics failures below are resolved in version 1.0.3. See [1.0.3 validation](RELEASE-1.0.3.md). This table preserves the original 1.0.2 results.

Tested October 28–29, 2026 on Apple Silicon macOS. Desktop tests used an isolated `com.livestreamstudio.qa` app so existing user playlists and destinations were preserved. Browser tests used localhost:3011 with actual FFmpeg endpoints. Stream keys are deliberately omitted.

## Verified streaming behavior

- Two destinations ran concurrently from the native app, both approximately 30 FPS, with separate sender telemetry. Combined observed upload was approximately 8.4–10 Mbps at two 4500 kbps video targets; audio/container overhead is additional and one-second measurements vary.
- Stopping destination A left B running at approximately 30 FPS and 4.75 Mbps.
- Simulate Drop now stops the actual sender, invokes normal recovery, waits the configured five seconds, and restores actual output. Previously it only painted a fake reconnection in the UI.
- Stop All returned both senders to idle, with zero active instances, zero combined upload, and no pending reconnect.
- The first authorized Unlisted YouTube broadcast automatically published and its Studio control room reported Excellent. The second sender ran successfully, but its control room initially showed No data and subsequent verification was interrupted by browser activity. **Successful publication of the second broadcast is not established.**
- A one-time schedule saved through the browser UI for October 29 at 13:13 Europe/Amsterdam launched a real RTMP stream to a local receiver and stopped after one minute. FFprobe confirmed H.264 1920×1080 + AAC, duration **60.255 seconds**, size **7,362,775 bytes**. Its persisted schedule shows Completed. This verifies actual timed start/stop through the browser backend; the one-hour boundary is covered by automated clock tests rather than an hour-long wait.

## Fixes included

Validated imports; accurate custom-path metadata; nonblocking notices with dismiss/timeout; native clipboard and text-save commands; accessible names for reorder/remove/preview actions; stop while connecting; real drop/recovery; configurable retry interval; profile URL/FPS controls; one-time local scheduling and launch deduplication; secure profile-key hydration; macOS idle-sleep prevention while configured schedules/streams are active. Intentional upload-buffer closure no longer reports a clip-encoder failure.

## Validation and limits

- Production TypeScript/Vite build passes.
- Node suite: **37 passed**; includes real local RTMP clip/repeat capture and one-hour scheduling boundary checks.
- Native suite: **14 passed**, one opt-in YouTube smoke test ignored in this run. A separately authorized prior smoke test passed.
- This is **not an all-features-pass certification**. Failed, blocked and incomplete items above remain explicit.
- Schedules require Studio to remain open. macOS idle-sleep prevention does not launch a quit app, restart a powered-off Mac, or guarantee streaming with a closed laptop lid.
- YouTube Auto-start must be enabled for the broadcast. User confirmed both test broadcasts had it enabled. Google OAuth/broadcast creation is not implemented.
- Sender processes were stopped after the simultaneous tests. Final YouTube End Stream confirmation could not be established through desktop control; check the control rooms if Auto-stop is disabled.
- Installer is an Apple Silicon build without Apple Developer ID notarization. Intel, Windows and Linux packages were not built or certified here.
